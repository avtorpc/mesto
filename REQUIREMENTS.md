# Место — актуальные требования

Актуально на **4 октября 2026 года**.

Документ определяет согласованное поведение прототипа, которое следует сохранять при дальнейшей разработке. Здесь нет истории отменённых решений. Описание реализации, запуск и структура файлов находятся в [README.md](README.md).

При согласовании нового поведения нужно изменять соответствующий раздел этого документа, а не добавлять противоречащее уточнение в конец. README обновляется, когда меняются готовые возможности, запуск или ограничения.

## 1. Объём и оформление

- HTML-прототип включает главную с разделами «Вакансии» и «Работники», резюме работодателя и резюме владельца, регистрацию и кабинет соискателя с несколькими резюме, кабинет работодателя и форму создания / редактирования вакансии.
- Светлый фон, серая палитра с допустимыми металлическими оттенками, контрастный текст и единый стиль карточек.
- HTML, CSS, JavaScript и изображения хранятся отдельно. Страницы открываются локально без сборки и сервера.
- Макет адаптируется к мобильному экрану. Горизонтальная прокрутка допустима внутри меню резюме, но не у всей страницы.
- В мобильном каталоге остаются доступны поиск, города, своё резюме, навыки и требования; прочие фильтры боковой колонки в текущем прототипе скрыты. При просмотре резюме карточка действий переносится над содержательными разделами; в редакторе владельца — под них.
- Основные действия доступны с клавиатуры и имеют понятные подписи. Настройка уменьшения анимации учитывается.

## 2. Главная и разделы

- Шапка содержит логотип, «Вакансии», «Работники» и «Войти». Отдельной вкладки избранного нет; закладки на карточках сохраняются.
- Оба каталога используют одинаковую композицию: вводный блок, поиск, популярные специальности, фильтры, дневная навигация, результаты и сортировка.
- Во вкладке работников отображаются резюме; текст интерфейса и источники фильтров соответствуют кандидатам.
- При переключении каталогов текущие поля и флажки очищаются, сортировка возвращается к новизне, дата — к сегодня. Сохранённые наборы фильтров остаются раздельными.
- Карточки вакансий показывают компанию, должность, зарплату, город, формат и опыт; карточки резюме — имя, специальность, ожидаемый доход и сведения о кандидате.
- В списке вакансий есть «Откликнуться» для быстрого отклика и «Подробнее» для полного описания на отдельной странице `vacancy.html?id=…`. Во вкладке работников «Подробнее» открывает резюме; кнопки быстрого отклика нет.
- Предусмотрены сортировка по новизне или доходу, дополнительные результаты и понятное пустое состояние.

## 3. Поиск и фильтрация

### Текст и специальность

- Общий поиск учитывает название, компанию / имя кандидата и описание.
- Специальность вводится свободно или выбирается из подсказок текущего каталога. Подбор обновляется при вводе, допускает частичное название и несколько слов.
- Поиск специальности не зависит от регистра, крайних пробелов и различия «е» / «ё»; все введённые слова должны встречаться в названии или специальности.
- В быстрых предложениях показаны три специальности по числу записей текущего каталога; при равенстве — по алфавиту. Подписи: «Самые востребованные» для вакансий, «Популярные специальности» для работников.
- Нажатие предложения заполняет специальность, очищает общий запрос и обновляет выдачу и связанные списки.

### Города, формат, доход и опыт

- Города выбираются флажками, допускается несколько значений. Совпадение с любым выбранным городом подходит; пустой выбор означает все города.
- «Очистить выбор» в списке городов снимает только города.
- «Удалённая работа» не является городом или специальностью. Она доступна как «Удалённо» в формате работы.
- Города, форматы и уровни опыта формируются из данных текущего каталога.
- Зарплата вакансий фильтруется по нижней границе «от», ожидаемый доход кандидатов — по верхней границе «до».
- Значения внутри каждой группы флажков объединяются по правилу «хотя бы одно». Между группами применяется совместное ограничение.

### Навыки и требования

- Под полем специальности расположен блок навыков, затем «Основные требования» для вакансий или «Квалификация и качества» для работников.
- Оба списка автоматически строятся из подходящих по специальности и общему запросу записей. Без запроса используются все записи текущего каталога.
- Значения сортируются по частоте, затем по названию. Повтор значения в одной записи не увеличивает счётчик.
- Число рядом со значением показывает количество записей с ним. Города, доход, опыт, формат и выбранный день не меняют эти счётчики.
- Несколько выбранных навыков означают совпадение хотя бы с одним; аналогично требованиям. Пустая группа выдачу не ограничивает.
- При обновлении списков сохраняются доступные выбранные значения, отсутствующие исключаются из фильтрации.
- При отсутствии подходящих записей показывается сообщение с предложением изменить запрос.

## 4. Активные и сохранённые фильтры

- Над выдачей отображаются активные значения с крестиками. Удаление одного значения сохраняет остальные и синхронно обновляет поля, флажки, выдачу и счётчик.
- Удаление запроса или специальности пересчитывает навыки и требования. Фокус после удаления переходит к соседнему действию или кнопке открытия окна фильтров.
- «Выбранные фильтры» открывает окно со всеми активными условиями по группам и их количеством. Список и теги используют одно состояние.
- В окно входят запрос, специальность, города, формат, доход, опыт, навыки и требования / квалификация. Дата и сортировка фильтрами не считаются.
- Без активных условий показывается пустое состояние.
- «Сбросить все» очищает текущие условия, но не выбранную дату и не сохранённый набор.
- «Сохранить фильтры» сохраняет один набор на каталог; повторное сохранение заменяет его. Пустой набор сохранить нельзя.
- «Применить сохранённые» восстанавливает условия после сброса или перезагрузки. Наборы двух каталогов не смешиваются.
- В прототипе хранение локальное с явным пояснением. Ошибка сохранения не должна сопровождаться сообщением об успехе.
- После подключения аккаунтов сохранение должно быть связано с зарегистрированным пользователем; сейчас авторизация не имитируется как успешная.

## 5. Выдача по дням

- По умолчанию отображаются только записи текущего дня: «Вакансии, открытые сегодня» или «Резюме, опубликованные сегодня».
- «+1 день назад» сдвигает дату на один календарный день назад. Показывается отдельный день, а не накопительный период.
- «На день вперёд» и «Сегодня» позволяют вернуться; будущие даты недоступны.
- Дни без результатов не пропускаются. Пустая выдача предлагает изменить условия или день.
- При смене дня сохраняются фильтры, выдача начинается с первой порции.
- Используется часовой пояс Europe/Moscow. В демоданных даты привязаны к дню открытия страницы.

## 6. Переходы к резюме

| Действие | Результат |
| --- | --- |
| «Вакансии» → «Личный кабинет и резюме» | Кабинет `user.html`, без демосеанса — регистрация |
| «Вакансии» → «Откликнуться» | Окно выбора резюме, необязательного задания и подтверждения отклика |
| «Вакансии» → «Подробнее» | Полная страница `vacancy.html?id=…` с тем же сценарием отклика |
| «Работники» → «Подробнее» | Страница работодателя `resume.html?id=…` |
| Владелец → «Посмотреть глазами работодателя» | Черновик в `resume.html?id=…&preview=1` и ссылка возврата |

- «Личный кабинет и резюме» находится над фильтрами только во вкладке вакансий, включая мобильный экран. Карточка содержит один основной заголовок и подпись «Резюме, отклики и чаты с работодателями», без дублирования «Мои резюме». Она открывает кабинет соискателя; без демосеанса — регистрацию.
- Пример ID 101 остаётся доступным отдельно. Из кабинета открываются личные резюме по своим ID. Реальная проверка прав потребует сервера.
- Подробные страницы поддерживают все демонстрационные ID. Без ID открывается 101; неизвестный ID показывает сообщение и ссылку возврата.

## 7. Содержимое резюме

- Общая шапка, переход обратно, дата публикации, номер резюме, имя, инициалы, специальность, город, формат, стаж и краткое описание.
- Разделы: «О себе», «Профессиональный опыт», «Ключевые навыки», «Образование» с языками, «Избранный проект».
- В блоке опыта первично связное краткое описание компетенций и решаемых задач, затем ключевые результаты.
- Компании, должности и периоды — вторичный список «Места работы», свёрнутый по умолчанию и доступный для раскрытия.
- Текст, подписи, даты и навыки должны быть тёмными и читаемыми.
- Боковая карточка содержит ожидаемый доход, условия и действия соответствующего режима.

### Навигация и выделение

- Все содержательные разделы отображаются одновременно; меню не скрывает их вкладками.
- «О себе · Опыт · Навыки · Образование · Проекты» закрепляется при прокрутке и переводит к выбранному блоку с отступом под меню.
- Текущий пункт и блок определяются при нажатии и ручной прокрутке. Сохраняются ID в адресе и ссылки на разделы.
- Блок выделяется мягким светло-серым фоном, без рамки. Клавиатурный фокус меню обозначается фоном.
- Номер активного блока увеличивается с 10 до 20 px и становится темнее; предыдущий возвращается к обычному виду.
- При печати скрываются действия и меню, снимается активная подсветка и увеличение номера.

### Режим работодателя

- Закладка резюме согласована с локальными закладками каталога.
- Приглашение открывает форму вакансии и сообщения; проверка формы не выполняет реальную отправку.
- Кнопка печати вызывает системное окно, в котором можно сохранить PDF.

## 8. Режим владельца

- Заголовок «Моё резюме», предпросмотр и управление видимостью. Пояснение о создании нового черновика не выводится.
- Все поля редактируются непосредственно в основном блоке страницы. Всплывающий редактор и кнопки «Заполнить резюме» / «Изменить» не используются.
- Редактируются имя, специальность, доход, город, формат, краткое описание; отдельно — о себе, стаж, описание опыта, результаты, места работы, навыки, квалификация, образование, языки и проект.
- Места работы вводятся отдельными записями с полями компании, должности и периода. При загрузке старых черновиков сохраняются ранее введённые компания, должность и период.
- Разрешено сохранять незавершённый черновик с пустыми полями. «Сохранить изменения» сохраняет все разделы; при уходе с несохранёнными правками показывается предупреждение браузера.
- Черновик сохраняется по ID, восстанавливается после перезагрузки и доступен в предпросмотре. Исходные данные каталога и обычный просмотр работодателя не меняются.
- Заголовок блока о себе — «Заполните основную профессиональную информацию о себе»; у навыков и квалификации есть поясняющие плейсхолдеры.
- Места работы, образования, языки и проекты добавляются отдельными повторяемыми записями компактными кнопками «−» и «+» рядом с полями и могут удаляться по одному; все записи сохраняются и выводятся в предпросмотре. Старые одиночные поля восстанавливаются как первая запись.
- Надпись «Можно сохранить незавершённое резюме.» выполняет сохранение, как основная кнопка.
- «Удалить резюме» с подтверждением удаляет только текущую запись пользователя и возвращает в кабинет. У старого демопримера удаляется только локальный черновик.
- При ошибке сохранения данные остаются в форме и показывается сообщение.
- Переключение видимости обозначается как демонстрационное и сохраняется локально; реальная публикация или скрытие не выполняется.

### Краткое описание, стаж и сохранение

Краткое описание — необязательное представление в 1–2 предложениях для шапки резюме; поле содержит подсказку. Общий стаж задаётся числом лет или месяцев либо вариантом «Без стажа». Можно оставить стаж неуказанным. После успешного сохранения показываются анимация копии страницы и сообщение «Резюме сохранено», без перезагрузки и потери позиции прокрутки. При уменьшении движения в настройках системы показывается только сообщение. При ошибке хранилища эффект успеха не запускается.

## 9. Вход и окна

- «Войти» доступна в общей шапке, в том числе на мобильном экране; открывает окно с вкладками входа и регистрации, по умолчанию — вход.
- Вход требует email и пароль. Регистрация — имя, цель (найти работу / работников), email и пароль не короче восьми символов.
- Проверяются обязательные поля и формат email. Формы не создают реальный аккаунт, не авторизуют и не сохраняют пароли; при закрытии очищаются. Деморегистрация работодателя открывает кабинет и сохраняет профиль в хранилище сеанса для последующей подстановки в вакансии.
- Диалоги закрываются крестиком, Escape и по внешнему фону. В окне фильтров также есть «Готово». Резюме редактируется без диалога.
- Демонстрационные действия не должны выдавать себя за реальную отправку, регистрацию или публикацию.

## 10. Создание вакансии работодателем

- Над формой закреплено меню «Кого ищем · Условия · Задачи и ожидания · Задание · Компания · Соискатели и чаты», оформленное как меню резюме. Все блоки видны одновременно; меню прокручивает к выбранному блоку и отслеживает ручную прокрутку. Активный блок подсвечивается фоном без рамки, номер основного раздела увеличивается. Ссылка на раздел сохраняется в адресе вместе с ID вакансии. На мобильном экране меню прокручивается горизонтально.

- На вкладке «Работники» доступен переход в кабинет работодателя; из кабинета открывается отдельная страница создания вакансии в общем стиле.
- Форма включает пять самостоятельных карточек. «04 · Проверочное задание» находится после «03 · Задачи и ожидания» и перед «05 · Компания и контакт»; оно не вложено в карточку задач.
- Поля формы: название, специальность, опыт; формат, занятость, города, доход, график; краткое описание, задачи, навыки, требования, преимущества; компания и контакт.
- Обязательны название, специальность, опыт, формат, занятость, описание, задачи, хотя бы один навык и требование, компания, контактное лицо и корректный email.
- Города обязательны для офиса и гибрида, для удалённого формата — нет. Несколько городов вводятся через запятую.
- Доход: хотя бы одна граница либо «по договорённости». Отрицательные суммы и диапазон с верхней границей ниже нижней не принимаются. При выборе договорённости поля сумм отключаются.
- Навыки выбираются тегами, основные требования вводятся отдельными полями. Значения предназначены для последующей фильтрации опубликованных вакансий. Прототип не добавляет их в общий каталог.
- Предпросмотр проходит валидацию, показывает публичные сведения и скрывает контактный email. Реальной публикации нет.
- Вакансию можно сохранить незавершённой; несколько записей хранятся отдельно по ID. Редактирование восстанавливает выбранную запись, повторное сохранение обновляет только её. При ошибке данные остаются в форме.
- Готовность отображается по пяти разделам: «01 · Кого ищем», «02 · Условия работы», «03 · Задачи и ожидания», «04 · Проверочное задание», «05 · Компания и контакт». При отключённом задании его раздел отмечается как «не требуется» и не препятствует готовности вакансии. Поля со звёздочкой и сообщения об ошибках объясняют, что требуется заполнить.
- Оценка регистрации работодателя находится в `EMPLOYER_REGISTRATION.md` и остаётся предложением до согласования; реальная авторизация не реализована; демосценарий описан ниже.

### Основные требования

В разделе «03 · Задачи и ожидания» основные требования вводятся по одному в отдельное поле. Рядом с каждой строкой расположены компактные «−» и «+». Последнюю строку можно очистить; для предпросмотра необходимо хотя бы одно заполненное требование. Пустые дополнительные строки не включаются в описание. Все требования сохраняются в черновике и восстанавливаются отдельными полями, включая старые записи с переносами строк.

### Навыки тегами и последовательность сохранения

Ключевые навыки выбираются тегами из подсказок по введённому слову. Подсказки составляются из навыков демонстрационных вакансий и резюме. Поддерживаются выбор мышью, стрелки, Enter, Escape, добавление собственного навыка и удаление тега крестиком; повторные теги не добавляются. Выбранные теги восстанавливаются из черновика и показываются в предпросмотре.

«Сохранить и в кабинет»: блокировка повторного нажатия → имитация ожидания AJAX → запись черновика → анимация копии страницы и подтверждение → переход в кабинет работодателя. «Сохранить черновик» выполняет ту же последовательность без перехода. Настоящего запроса к серверу нет. При ошибке записи переход и анимация успеха не выполняются, поля сохраняются на экране, доступна повторная попытка. При уменьшении движения анимация заменяется подтверждением.

## 11. Цепочка регистрации работодателя

- «Работники → Кабинет работодателя» открывает регистрацию работодателя либо кабинет при наличии демопрофиля.
- Дополнительно к имени, email и паролю показаны тип и публичное название работодателя; название обязательно. Для соискателя эти поля скрыты и не участвуют в валидации.
- «Перейти в кабинет» проверяет форму, сохраняет демопрофиль на время сеанса и открывает кабинет работодателя. Пароль не записывается в хранилище или URL.
- Компания, контактное лицо и email подставляются в пустые поля формы; существующий черновик имеет приоритет.
- Сценарий доступен также из общей регистрации с ролью работодателя на всех страницах.
- Закрытие регистрации не считается её завершением. Ошибка хранилища оставляет пользователя на форме с пояснением.
- Реальный аккаунт, подтверждение email и публикация не выполняются; интерфейс явно обозначает деморежим.

## 12. Кабинет работодателя и список вакансий

- Создание вакансии вызывается из кабинета работодателя после регистрации.
- Список содержит все локально сохранённые вакансии текущего демокабинета: название, статус черновика, условия, дата изменения и переход к редактированию.
- При отсутствии записей показаны пояснение и действие создания первой вакансии. Поиск без совпадений не выдаётся за пустой кабинет.
- Новая вакансия получает отдельный ID. Повторное сохранение обновляет выбранный ID без дублирования и изменения других записей.
- «Сохранить и в кабинет» переходит к списку только после успешного сохранения. При ошибке данные остаются в форме.
- Для неизвестного ID выводится сообщение, сохранение в несуществующую запись недоступно.
- Возврат в кабинет обновляет список; доступен поиск по названию. Реальная публикация и авторизация не выполняются.


## 13. Регистрация соискателя и несколько резюме

- Обязательные поля регистрации отмечены `*`: имя, цель, email и пароль от 8 символов. Для работодателя сохраняются его дополнительные поля.
- Соискатель после отправки формы попадает на подтверждение email, а не сразу в кабинет.
- Отправка письма имитируется: код виден в демонстрационном письме, привязан к введённому адресу, действует 5 минут и заменяется повторной отправкой. Неверный / истёкший код не завершает шаг; после пяти ошибок требуется новый.
- Можно исправить email, отменить регистрацию, запросить код заново. Отмена и закрытие окна удаляют ожидаемое подтверждение.
- Только правильный код создаёт демосеанс с подтверждённым email. Пароль и код не сохраняются как учётные данные.
- Кабинет соискателя показывает профиль и список нескольких резюме; без сеанса предлагает регистрацию.
- Создание сразу открывает новый пустой черновик на странице владельца, без предварительного запроса должности и города. У документа свой ID, он скрыт по умолчанию и не содержит чужой биографии. Должность и город заполняются на странице владельца.
- Редактор владельца и предпросмотр работают с выбранным личным документом. Сохранение не затрагивает другие резюме и каталог демонстрационных кандидатов.
- Список резюме хранится локально отдельно по email; сеанс — до его завершения. Это демонстрационное разделение, не защита доступа.
- Сценарий работодателя и отдельные примеры резюме 101–106 сохраняются.

## 14. Проверочные задания и оценка отклика

- Задание необязательно и настраивается при создании / редактировании вакансии в отдельном разделе «04 · Проверочное задание». Отключение задания исключает его из просмотра и сценария отклика; сохранённые поля настройки могут оставаться в черновике.
- Типы: анкета, алгоритмическая задача, предложение по реструктуризации. Название, описание и баллы обязательны при включении; вопросы обязательны только для анкеты. Ориентировочное время необязательно.
- Баллы за полный ответ задаются работодателем от 1 до 100; начальное значение — 10. Это баллы за выполнение, а не доказательство качества ответа.
- Информационный блок расположен в начале просмотра вакансии и предпросмотра. Он показывает содержание, вопросы, время, баллы и возможность пропуска. Без задания указано, что можно отправить резюме сразу.
- Отклик доступен двумя путями: напрямую из списка и с полной страницы вакансии. Оба используют один сценарий и идентификатор вакансии.
- Быстрый отклик сразу показывает выбор резюме и сообщения, а при наличии задания — его название, ориентировочное время, баллы и предложение выполнить либо пропустить.
- Отдельного шага проверки или подтверждения отклика нет. Без задания и при одном доступном резюме отклик сохраняется одним нажатием кнопки в списке / на полной странице. При нескольких резюме показан выбор и одна кнопка «Откликнуться».
- Для вакансии с заданием доступны «Решить задание» и «Откликнуться без задания». Второе действие сразу сохраняет отклик без прохождения следующих форм. «Выполнено — откликнуться» сразу сохраняет полный ответ и отклик вместе.
- Полная страница вакансии содержит все публичные сведения из каталога: компанию, доход, город, формат, опыт, описание, задачи, навыки, требования и информационный блок задания. Есть кнопка отклика и возврат в список. Неизвестный ID не подставляет другую вакансию.
- При подтверждённом демосеансе выбирается одно из личных резюме. Если их нет, предлагается создать резюме. Без демосеанса доступен явно обозначенный пример Анны Морозовой.
- Анкета требует непустого ответа на каждый вопрос. Алгоритм и предложение принимаются как текст; код не запускается. Пробелы не считаются заполненным ответом.
- Соискатель может пропустить задание и продолжить отклик; в этом случае баллы за выполнение равны 0. До сохранения баллы не начисляются.
- Сохранение полного ответа начисляет заданное число баллов только в этом отклике. Повторный отклик того же email на ту же вакансию обновляет запись, не создаёт дубликат и не накапливает баллы.
- В кабинете работодателя показаны отклики, резюме, сопроводительное сообщение и ответы. Выполненный ответ можно оценить вручную от 0 до 100 с необязательным комментарием. Оценка принадлежит этой вакансии, не является общим рейтингом человека и не суммируется с баллами за участие.
- В кабинете соискателя показаны баллы за выполнение, статус задания и оценка работодателя. До проверки качество не считается оценённым. Изменение ответа или задания сбрасывает прежнюю оценку; повторная отправка того же ответа её сохраняет.
- Для проверки черновика работодатель сначала сохраняет его, затем использует «Проверить отклик (демо)» в предпросмотре. Черновик не виден в общем каталоге до отдельной команды «Опубликовать в прототипе».
- На главной есть три демонстрационных задания; остальные вакансии дают сценарий без задания.
- Отклики и оценки сохраняются локально. Ошибка записи не сопровождается успешным начислением баллов; введённые ответы остаются на экране. Реальная отправка, серверная авторизация и автоматическая оценка качества отсутствуют.

### Этап показа задания соискателю

1. В списке вакансий при наличии задания показываются его необязательность и баллы за выполнение; сама карточка не требует решения.
2. При наличии задания «Откликнуться» открывает выбор резюме. Название задания, время и баллы показаны до решения о прохождении. «Решить задание» переводит к решению, «Откликнуться без задания» сразу отправляет отклик.
3. «Подробнее» открывает полную страницу вакансии. Информационный блок показывает тип, название, условия, вопросы анкеты, время, баллы и возможность пропуска. Отклик запускает тот же сценарий.
4. На шаге выполнения показываются условия и поля ответа. «Выполнено — откликнуться» требует непустого решения или всех ответов анкеты и сразу отправляет их вместе с откликом. «Откликнуться без задания» сразу отправляет отклик без ответов.
5. Дополнительного экрана проверки и второй кнопки подтверждения нет. До успешного сохранения баллы не начисляются. При ошибке форма и ответы остаются доступны для повторной отправки.
6. После сохранения окно отклика автоматически закрывается. На исходной странице ненадолго показываются подтверждение и число начисленных баллов без кнопок. Отдельного окна успеха, предложения перейти в чаты и дополнительного клика закрытия нет. Чат остаётся доступен в кабинете; оценка качества ответа ожидает проверки работодателем.

- Без задания отсутствуют выполнение и проверка; одно доступное резюме отправляется сразу, несколько требуют только выбора и отправки.
- Закрытие окна не создаёт отклик и не начисляет баллы. Сохранение незавершённых ответов между открытиями пока не реализовано.
- Переход назад внутри открытого окна сохраняет введённый ответ. Ошибка сохранения не очищает данные и не выдаётся за успех.

## 15. Отклики и чаты соискателя

Поведение этой итерации принято: фильтры, их порядок и выбор приглашений по умолчанию считаются текущими требованиями.

- В кабинете соискателя список откликов представлен разделом «Отклики и чаты». Каждая запись связана с конкретной вакансией и компанией; повторный отклик не создаёт второй чат и не удаляет сообщения.
- Список содержит название вакансии, компанию, последнее сообщение, дату и статус отклика. Поиск учитывает вакансию и компанию; сортировка — по последней активности.
- Фильтры: «Все», «Отказы», «На рассмотрении», «Без ответа», «Приглашения», «Избранные», со счётчиками. По умолчанию выбраны «Приглашения» при каждом новом открытии страницы. Если их нет, другие статусы не показываются; доступна кнопка просмотра всех откликов.
- Фильтр сочетается с поиском. Счётчики отражают все отклики текущего соискателя в каждой категории независимо от поиска.
- Новый отклик — «Без ответа». Сообщение или оценка работодателя переводят его в «На рассмотрении», но не меняют уже заданные приглашение или отказ. Работодатель может установить статус вручную; изменение видно в чате.
- «Избранные» — независимая отметка соискателя для любого статуса. Кнопка в чате добавляет / удаляет её, отметка переживает перезагрузку и повторный отклик; на баллы и оценку качества не влияет.
- Старые отклики без явного статуса определяются как «На рассмотрении» при наличии ответа / оценки работодателя, иначе — «Без ответа».
- Выбор записи открывает диалог рядом со списком. На мобильном экране список расположен над перепиской.
- Чат содержит отправленное резюме, сопроводительное сообщение, ответы на задание, уведомление о баллах и сообщение работодателя с оценкой и комментарием. Новая версия отклика добавляется в историю. Текущая оценка отображается отдельно от старых сообщений.
- Доступны сообщения соискателя и работодателя. В кабинете работодателя чат открывается внутри выбранного отклика. Реальная доставка отсутствует; данные хранятся в одном браузере.
- Разрешено сохранение непустого сообщения до 5000 символов. Пробелы не считаются сообщением. При ошибке текст остаётся в поле, успешное сохранение не имитируется.
- Сообщения отображаются как текст, включая фрагменты кода и HTML. ID отклика и email связывают переписку с нужной записью; локальные проверки не заменяют серверные права доступа.
- Старые отклики автоматически получают представление чата; остальные резюме и отклики не изменяются.
- Для вакансий каталога есть переход к полному описанию. При отсутствии откликов показано предложение найти работу; при отсутствии совпадений поиска — отдельное сообщение.
- Переключение между чатами сохраняет незавершённый текст в пределах открытой страницы. После перезагрузки незавершённый текст не восстанавливается. Новые данные из другой вкладки обновляют список без смешивания переписок.

## 16. Чаты работодателя по вакансии

- На странице редактора вакансии отдельный раздел «Соискатели и чаты»; переход из меню и из карточки вакансии в кабинете работодателя.
- Список ограничен ID выбранной вакансии и email текущего демокабинета. По умолчанию видны все её отклики.
- Слева имя и данные соискателя: резюме, email, навыки, статус, последнее сообщение и дата. Поиск и фильтры статусов не смешивают вакансии.
- Справа выбранная общая переписка, отправка сообщений, изменение статуса, ответы на задание и ручная оценка соответствия. Изменения видны соискателю в том же локальном хранилище.
- Переключение чата сохраняет неотправленный текст сообщения в пределах страницы. Ошибка отправки или оценки оставляет введённый текст.
- Несохранённая / неизвестная вакансия, отсутствие откликов, отсутствие совпадений и ошибка чтения имеют отдельные сообщения. Чат не вложен в форму вакансии.
- Проверка: отклики на две вакансии показываются раздельно; ответ, приглашение и оценка относятся только к выбранному соискателю; демонстрационный отклик обновляет список без перезагрузки.

## 17. Локальная публикация вакансии и полный цикл отклика

- В редакторе кнопка «Опубликовать в прототипе» проверяет обязательные поля и сохраняет вакансию с подтверждением. Публикация неполной формы блокируется; обычный черновик можно сохранить незавершённым.
- Опубликованная вакансия появляется в общем каталоге этого браузера с датой публикации, навыками, требованиями, городами и необязательным заданием. Доступны поиск, фильтры, быстрый отклик и отдельная полная страница.
- Публичная вакансия доступна при смене демопрофиля; отклик связан с исходным работодателем и ID вакансии. Предпросмотр, список и полная страница используют одну запись отклика.
- В кабинете статус «Опубликована · прототип», отдельный подсчёт черновиков и ссылка «Открыть страницу глазами соискателя».
- Повторная публикация не создаёт дубликат и не меняет первый день публикации. Сохранение редактируемых полей сохраняет статус; публичная версия меняется отдельной кнопкой «Обновить публикацию».
- При ошибке нет подтверждения успешной публикации; поля остаются в редакторе. Тексты работодателя в каталоге отображаются безопасно как текст.
- Проверка: публикация → отклик из общего интерфейса → появление соискателя в чате правильного работодателя → ответ / приглашение / оценка. Чужие вакансии и черновики не подмешиваются.

- Видимость публикаций: на главной переключатель между выбранным днём и всеми локальными публикациями работодателей. Публикация предыдущего дня доступна во втором режиме; фильтры и быстрый отклик работают в обоих.
- Редактор показывает дату публикации и прямую ссылку на её поиск в главном каталоге. Отметка «Опубликована» подтверждается наличием публичной записи, расхождение и ошибки хранилища не скрываются.
