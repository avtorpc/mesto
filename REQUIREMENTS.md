# Требования к HTML-прототипу сайта поиска работы

Дата фиксации: 2 октября 2026 года.

Документ фиксирует согласованные в чате требования и текущее поведение прототипа. Последующие уточнения заменяют предыдущие решения: пункт «Удалённая работа» удалён из списка городов, города поддерживают множественный выбор, а поле специальности поддерживает ввод текста вместо ограниченного выпадающего списка.

## 1. Назначение и объём

- Создать визуальный HTML-прототип главной страницы сайта поиска работы.
- На текущем этапе сосредоточиться на макете и взаимодействиях пользователя.
- Использовать демонстрационные вакансии; подключение к реальным работодателям и серверной части не входит в текущий этап.
- Рабочее название проекта в прототипе — «место».

## 2. Визуальное оформление

- Светлый фон.
- Серая цветовая гамма с оттенками; допустимы металлические оттенки и декоративные элементы.
- Чёткая типографика, свободные отступы, аккуратные карточки и единое оформление фильтров.
- Адаптивная вёрстка для компьютера и мобильных экранов.

## 3. Структура проекта

HTML, стили, JavaScript и изображения хранятся отдельно:

```text
html/
  index.html       — главная страница
css/
  styles.css       — стили и адаптивная вёрстка
js/
  main.js          — данные прототипа и интерактивность
images/            — изображения проекта
README.md          — инструкция по открытию прототипа
REQUIREMENTS.md    — этот документ
```

- Папка проекта: `/Users/user/Documents/__HH__`.
- Точка входа: `html/index.html`.
- Использовать относительные пути к ресурсам.
- Прототип открывается в браузере без установки зависимостей и запуска сервера.
- Папка изображений пока может оставаться пустой: текущие декоративные элементы выполнены средствами CSS и встроенных SVG.

## 4. Главная страница

Текущая композиция:

- Шапка с логотипом, переходом к вакансиям, избранным и кнопкой для работодателей.
- Вводный блок с заголовком и формой поиска.
- Поиск по должности, компании или ключевому слову.
- Выбор одного или нескольких городов.
- Левая колонка фильтров на широком экране.
- Список вакансий, открытых сегодня, с количеством результатов, сортировкой и переходами по календарным дням.
- Карточки с названием вакансии, компанией, зарплатой, городом, форматом работы и опытом.
- Просмотр подробного описания вакансии.
- Добавление вакансий в избранное и просмотр избранного.
- Кнопка показа дополнительных вакансий.

Мотивационный блок «Следующий шаг — ваш» удалён. Вместо него размещены блок навыков и расположенный ниже блок основных требований.

## 5. Общие фильтры

- Формат работы: удалённо, в офисе, гибрид.
- Минимальная зарплата.
- Опыт работы.
- Один или несколько городов.
- Название вакансии / специальность.
- Навыки.
- Основные требования.

Фильтры разных групп применяются совместно. Выбранные значения отображаются над списком вакансий. Кнопка «Сбросить» очищает поля поиска, специальность, город, зарплату и выбранные флажки, возвращая общие списки навыков и требований.

## 6. Выбор городов

- Список городов раскрывается в форме поиска и позволяет отметить несколько городов флажками.
- Города формируются из данных вакансий. Пункта «Удалённая работа» в списке городов и специальностей нет.
- Если города не выбраны, поиск ведётся по всем городам, подпись поля — «Любой город».
- При выборе нескольких городов показываются вакансии из любого выбранного города. Остальные фильтры применяются совместно.
- Выбор применяется сразу; список остаётся открытым для выбора следующих городов.
- «Очистить выбор» снимает только выбор городов.
- Удалённый формат доступен через отдельный фильтр «Формат работы → Удалённо».

## 7. Поле специальности / названия вакансии

- Поле находится вверху блока навыков и имеет подпись «Специальность».
- Пользователь может свободно вводить название вакансии, а также выбирать подсказки.
- Подсказки формируются из специальностей, указанных в данных вакансий.
- Подбор вакансий обновляется по мере ввода, без обязательного выбора точного названия из списка.
- Допускается частичное название: «дизайнер» находит продуктового и графического дизайнеров.
- Поиск не зависит от регистра, игнорирует крайние пробелы и различие «е» / «ё».
- Введённые слова сопоставляются с названием вакансии и её специальностью.
- Оба блока ниже — навыки и основные требования — обновляются по подходящим вакансиям.
- Общий текстовый поиск в верхней части страницы также влияет на состав обоих блоков.
- Если совпадений нет, показывается понятное сообщение с предложением изменить название.

## 8. Блок навыков

- Список формируется автоматически из навыков, указанных работодателями в вакансиях, а не из отдельного фиксированного перечня.
- Без введённого названия и общего поискового запроса отображаются наиболее востребованные навыки по всем демонстрационным вакансиям.
- Востребованность определяется количеством вакансий, в которых указан навык.
- Навыки сортируются по убыванию частоты; при одинаковой частоте — по названию.
- При вводе названия или выборе подсказки список составляется из подходящих вакансий.
- Каждый навык представлен выбираемым элементом с флажком и числом вакансий.
- Один и тот же навык учитывается не более одного раза в каждой вакансии.
- Можно выбрать несколько навыков: показываются вакансии хотя бы с одним выбранным навыком.
- Если навыки не выбраны, эта группа не ограничивает результаты.

## 9. Блок «Основные требования»

- Размещается непосредственно под блоком навыков.
- Использует такое же оформление: светло-серый контейнер, заголовок, пояснение, выбираемые элементы с флажками и количеством вакансий.
- Формируется автоматически из основных требований работодателей в вакансиях.
- Зависит от того же поля специальности / названия вакансии, что и блок навыков; отдельное поле названия не требуется.
- Без поискового запроса показывает наиболее частые требования по всем демонстрационным вакансиям.
- При вводе названия показывает только требования из подходящих вакансий, начиная с наиболее частых.
- Повтор одного требования внутри одной вакансии не увеличивает его частоту.
- Можно выбрать несколько требований: показываются вакансии хотя бы с одним выбранным требованием.
- Если требования не выбраны, эта группа не ограничивает результаты.
- Фильтр требований применяется совместно с навыками и другими фильтрами.
- Примеры демонстрационных требований: портфолио, коммерческий опыт, работа в команде, внимание к деталям, готовность учиться.

## 10. Обновление списков и счётчиков

- При изменении названия вакансии оба списка пересчитываются одновременно.
- Выбранные навыки и требования сохраняются, если они присутствуют в новом списке; отсутствующие больше не фильтруют результаты.
- При очистке полей поиска возвращаются общие списки, отсортированные по востребованности.
- Число рядом с навыком или требованием означает количество вакансий с этим значением в выборке по специальности и общему текстовому запросу.
- В текущем прототипе город, зарплата, формат работы, опыт и избранное фильтруют выдачу, но не пересчитывают состав и счётчики этих двух списков.

## 11. Дополнительное поведение текущего прототипа

- Сортировка: сначала новые или по уровню зарплаты.
- Избранное сохраняется локально в браузере, если локальное хранилище доступно.
- Подробности вакансии открываются в диалоговом окне и содержат задачи, навыки и основные требования.
- Реальная отправка отклика, публикация вакансий и кабинет работодателя не реализованы; используются пояснения о демонстрационном режиме.
- На мобильном экране блоки навыков и требований доступны над выдачей; остальные фильтры левой колонки в текущем макете скрыты.

## 12. Примеры проверки

1. Открыть `html/index.html`: без поискового запроса видны общие навыки и требования, отсортированные по частоте.
2. Ввести «дизайнер» в поле специальности: остаются вакансии дизайнеров, оба блока показывают данные из этих вакансий.
3. Ввести часть названия в другом регистре: подбор продолжает работать.
4. Выбрать подсказку конкретной специальности: вакансии, навыки и требования соответствуют выбору.
5. Выбрать навык и требование: выдача учитывает обе группы фильтров.
6. Изменить название: неподходящие выбранные значения удаляются из фильтрации.
7. Ввести название без совпадений: отображается сообщение об отсутствии подходящих вакансий.
8. Выбрать Москву и Казань: выдача содержит вакансии из любого из этих городов; снятие обоих флажков возвращает все города.
9. Нажать «Сбросить»: поля и флажки очищаются, общие списки восстанавливаются.

## 13. Окно выбранных фильтров

- Над выдачей расположена кнопка «Выбранные фильтры» с количеством активных значений.
- Кнопка открывает отдельное всплывающее окно, доступное на компьютере и мобильном экране.
- Окно показывает все активные условия по группам: поисковый запрос, специальность, города, формат работы, зарплата, опыт, навыки, основные требования, а также режим «Только избранные», если он включён.
- Несколько городов и несколько выбранных значений перечисляются полностью.
- Сортировка не считается фильтром и не включается в счётчик.
- Если фильтров нет, отображается пояснение «Фильтры пока не выбраны».
- «Сбросить все» очищает фильтры и режим избранного; окно остаётся открытым и обновляется.
- Окно закрывается крестиком, кнопкой «Готово», клавишей Escape или нажатием на фон за его пределами.
- Открытие и закрытие окна не изменяет выбор.
- Список в окне, счётчик кнопки и теги над выдачей формируются из одного набора активных условий.

## 14. Удаление отдельных фильтров

- Каждый активный фильтр над вакансиями имеет крестик удаления с доступной подписью.
- Удаление снимает только соответствующее значение; например, удаление Москвы сохраняет выбор Казани.
- Синхронно обновляются флажки и поля, выдача, счётчик и содержимое окна выбранных фильтров.
- При удалении поискового запроса или специальности пересчитываются связанные навыки и требования.
- После удаления фокус переходит на соседний крестик или кнопку открытия окна фильтров.

## 15. Сохранение фильтров

- Во всплывающем окне размещается кнопка «Сохранить фильтры».
- Целевое поведение: зарегистрированный пользователь сохраняет условия поиска в своём профиле.
- В текущем прототипе авторизация и сервер отсутствуют. Кнопка демонстрирует сохранение одного набора локально в браузере, что явно указано в окне; это не сохранение в реальном аккаунте.
- Сохраняются запрос, специальность, города, формат, зарплата, опыт, навыки, требования и режим избранного.
- Повторное сохранение заменяет ранее сохранённый набор.
- «Применить сохранённые» восстанавливает набор, в том числе после перезагрузки страницы, и обновляет все фильтры и выдачу.
- Пустой набор нельзя сохранить. Удаление отдельных фильтров и общий сброс не удаляют сохранённый набор.
- При недоступном хранилище показывается сообщение об ошибке без ложного подтверждения сохранения.

## 16. Востребованные специальности и вакансии по дням

- Под поиском вместо «Например» расположен блок «Самые востребованные».
- Три специальности определяются по числу вакансий во всей базе; при равной частоте — по алфавиту. В прототипе это демонстрационные данные, а не статистика рынка.
- Нажатие на специальность заполняет соответствующее поле и обновляет выдачу, навыки и требования.
- При открытии главной выводятся только вакансии, открытые сегодня, с заголовком «Вакансии, открытые сегодня».
- Каждая вакансия содержит дату публикации `publishedAt`. В прототипе даты распределены между сегодняшним и двумя предыдущими днями относительно момента открытия страницы.
- «+1 день назад» переводит на предыдущий календарный день; повторное нажатие — ещё на один день назад. Выдача показывает только выбранный день, не накопительный период.
- Предусмотрены кнопки «На день вперёд» и «Сегодня»; переход в будущие дни недоступен.
- При перелистывании отображается выбранная дата, сохраняются остальные фильтры, выдача начинается с первой порции.
- Дни без вакансий не пропускаются: показывается пустое состояние с возможностью выбрать другой день.
- Используется календарь часового пояса Europe/Moscow.
- В избранном отображаются сохранённые вакансии всех дат; дневная навигация скрыта.
- Выбранный день является режимом просмотра и не входит в сохраняемый набор фильтров. Сброс фильтров не меняет дату просмотра; для возврата есть кнопка «Сегодня».

## 17. Раздел «Работники» — актуальное изменение

Это изменение заменяет описанное выше поведение вкладки «Избранное».

- Навигация содержит вкладки «Вакансии» и «Работники». Отдельная вкладка избранного убрана, закладки на карточках сохранены.
- «Работники» предназначена для работодателей и повторяет композицию, оформление и основные взаимодействия вкладки вакансий.
- Вместо вакансий показываются резюме: имя, специальность, ожидаемый доход, город, формат работы, опыт и описание кандидата.
- Все списки фильтров формируются по данным текущего раздела: город, формат работы, опыт, специальность, навыки, требования / квалификация.
- Навыки и квалификация пересчитываются по поисковому запросу и специальности. Числа показывают частоту среди подходящих резюме.
- Доход в резюме фильтруется по верхней границе бюджета работодателя, в вакансиях — по нижней границе зарплаты.
- Вместо «Основных требований» в разделе работников отображается «Квалификация и качества».
- Резюме отображаются по дням публикации с теми же кнопками навигации.
- Сохранённые наборы фильтров вакансий и работников хранятся отдельно. Режим избранного больше не входит в набор.
- Переключение разделов очищает текущие условия и возвращает дату на сегодня.
- Карточка резюме открывает описание опыта и достижений, навыков и квалификации.
- В прототип добавлены шесть резюме вымышленных людей; авторизация, контакт с кандидатом и реальные приглашения не реализованы.

## 18. Кнопка «Войти» и окно авторизации

- Верхняя кнопка «Работодателям» заменена на «Войти», включая мобильную версию.
- Открывается отдельное окно с вкладками «Войти» и «Зарегистрироваться»; по умолчанию выбран вход.
- Вход: обязательные email и пароль. Регистрация: имя, цель использования, email и пароль длиной от 8 символов.
- Доступны переключение вкладок клавиатурой, закрытие крестиком, Escape и по фону. При закрытии фокус возвращается на кнопку входа.
- Формы проверяют обязательные поля и формат email. Отправка демонстрационная: не выполняется вход, не создаётся аккаунт и не сохраняются персональные данные или пароли.
- После отправки показывается пояснение о демонстрационном режиме; при закрытии поля очищаются.

## 19. Подробная страница резюме

- Отдельная страница `html/resume.html?id=101` в общей светлой серой стилистике. Параметр ID выбирает одно из шести резюме.
- Кнопка «Подробнее» во вкладке «Работники» ведёт на страницу соответствующего кандидата вместо прежнего окна. Подробности вакансий остаются в окне.
- Содержимое: данные кандидата, специальность, доход, условия, описание, опыт и достижения, навыки, квалификация, образование, языки, пример проекта.
- Общая шапка и окно авторизации; ссылка на список работников; навигация по разделам резюме.
- Поддержаны локальные закладки, демонстрационная форма приглашения и системная печать / сохранение в PDF.
- На мобильном экране боковая карточка действий переносится над подробностями.
- Несуществующий ID обрабатывается сообщением и ссылкой возврата. Все сведения вымышлены; сообщения и приглашения не отправляются.
- Общий источник данных `js/data.js`, общая логика авторизации `js/auth.js`; страница резюме использует `js/resume.js` и `css/resume.css`.

## 20. Читаемость и переходы внутри резюме

- Пункты «О себе», «Опыт», «Навыки», «Образование» прокручивают страницу к соответствующим разделам; выбранный пункт выделяется.
- Навигация закрепляется при прокрутке, целевой раздел учитывает её высоту. Сохраняются параметр ID и якорные ссылки.
- Основной текст в блоках «О себе», «Опыт работы», «Ключевые навыки», «Образование» — тёмный, близкий к чёрному. Дополнительные подписи и даты также имеют повышенный контраст.

## 21. Просмотр резюме владельцем

- Отдельный макет `resume-owner.html?id=…` с заголовком «Моё резюме», сообщением о локальном черновике и предпросмотром для работодателя.
- Владелец редактирует основную информацию и содержательные разделы через формы. Отмена закрывает форму без сохранения.
- Сохранение локальное, по ID резюме; исходный каталог и обычная страница работодателя не изменяются. Предпросмотр с `preview=1` использует черновик.
- Кнопки приглашения и закладки заменены действиями владельца; доступна демонстрационная настройка видимости.
- Авторизация и серверное управление доступом не реализованы: это прототип, а не защищённый личный кабинет.

### Переход к своему резюме с главной

На вкладке «Вакансии» над фильтрами находится карточка «Моё резюме». Она открывает `resume-owner.html?id=101` — страницу владельца с редактированием. Название берётся из локального черновика, если он сохранён. В прототипе используется демонстрационный профиль 101; после подключения авторизации ID должен определяться текущим пользователем. Во вкладке «Работники» эта карточка скрыта, а «Подробнее» продолжает открывать резюме для работодателя.

### Профессиональный опыт: описание прежде хронологии

В обеих версиях резюме основным содержимым блока опыта стало краткое связное описание компетенций и решаемых задач. Ниже показаны ключевые результаты. Компании, должности и периоды перенесены во вторичный сворачиваемый список «Места работы», закрытый по умолчанию. У владельца описание, результаты и список мест работы редактируются через «Изменить» в блоке профессионального опыта; для каждого места используется отдельная строка. Сохранённые ранее компания и год начала учитываются при загрузке старого черновика.

### Уточнение: вкладки вместо якорной прокрутки

Меню резюме теперь переключает содержимое: «О себе», «Опыт», «Навыки», «Образование», «Проекты». На экране показан только выбранный раздел, активный пункт выделяется белой плашкой. Это заменяет прежнее описание якорной навигации. Поведение одинаково для владельца и работодателя; редактирование доступно внутри выбранного раздела владельца. Поддержаны стрелки клавиатуры, Home и End. При печати отображаются все разделы независимо от выбранной вкладки.

### Текущий показ резюме: все блоки на одной странице

По последнему согласованию отменено скрытие разделов вкладками. «О себе», «Опыт», «Навыки», «Образование» и «Проекты» показываются одновременно. Верхнее меню закрепляется при прокрутке и переводит к выбранному блоку с учётом своей высоты. Текущий раздел выделяется также при ручной прокрутке. Поведение одинаково для владельца и работодателя; поддержаны ссылки на разделы и уменьшение анимации.
