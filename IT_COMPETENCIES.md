Дата: **5 октября 2026 года**. Статус: **предлагаемый каталог проверяемых областей**, не готовые тесты и не утверждённая матрица присвоения грейдов.

Связан со справочником [IT_SPECIALIZATIONS.md](IT_SPECIALIZATIONS.md) и принятой моделью [CATEGORIES_AND_GRADES.md](CATEGORIES_AND_GRADES.md).

Связь с постоянными критериями и условиями задач: [ASSESSMENT_CRITERIA_CATALOG.md](ASSESSMENT_CRITERIA_CATALOG.md). Для каждой из 65 компетенций подготовлен хотя бы один критерий; это стартовое покрытие, а не исчерпывающая экзаменационная программа.

## 1. Что подтверждаем

Технология — инструмент. Компетенция — способность выполнить определённую работу. Проверка связывает способность с конкретной технологией и областью: например «реализовал API на PHP», а не просто «знает PHP».

Квалификацию в целом нельзя подменять знанием синтаксиса. Дипломы, сертификаты, стаж и результаты ФСП относятся к отдельным доказательствам; тест платформы не выдаёт официальный документ об образовании и не подтверждает автоматически все обязанности профессии.

Слово «тест» включает практическую задачу, лабораторный сценарий, разбор кейса, объяснение решения и экспертную проверку. Опрос с вариантами ответов подходит для проверки отдельных знаний, но сам по себе не доказывает весь профессиональный уровень.

Не каждый кандидат должен проходить все перечисленные проверки. Он свободно выбирает области. Присвоение грейда зависит от отдельной опубликованной методики; ни одна строка ниже не объявлена обязательной для всех работников.

## 4. Как должна выглядеть запись результата

Пример условного результата:

> Компетенция: работа с транзакциями. Контекст: PHP + PostgreSQL. Проверено: выполнение заказа и поведение при заданном сбое. Результат: критерии этой проверки выполнены. Версия задания, дата и область оценки сохранены.

Запись включает компетенции, стек и версии, описание задачи, результат по критериям, использованные средства / разрешённую помощь, источник оценки, дату и ограничения применимости. Если общие знания проверены без технологического контекста, это отмечается явно и не становится доказательством практики на всех языках.

Статусы: «не заявлено», «заявлено», «не проверено», «подтверждено в указанной области», «не подтверждено этой попыткой». Последнее не означает, что человек вообще не владеет навыком.

Несколько компетенций могут проверяться одним заданием; одна компетенция может проверяться разными заданиями. Учитывать только те результаты и области, которые действительно оценивались, не начислять повторное подтверждение за одинаковое доказательство.

## 5. Связь с принятыми грейдами

Junior, Middle и Senior остаются уровнями конкретной специализации. Каталог описывает кандидатов через проверяемые способности и стек. Само наличие PHP, Docker или SQL в профиле не присваивает грейд.

Правило присвоения задаётся отдельно: какие результаты, области и уровни сложности достаточны, какие проверки равноценны. Пока такой методики нет, платформа показывает отдельные подтверждения и не назначает уровень по сумме случайных тестов.

Успешный тест по одной компетенции не повышает уровень всех других навыков. SQL и Docker не подтверждают Full Stack автоматически. Высокий уровень Backend на PHP не превращается в высокий уровень Python.

## 6. Что требует экспертного метода

Архитектура, UX-исследования, управление продуктом, оценка рисков и объяснение решений обычно имеют несколько допустимых ответов. Для них нужна опубликованная шкала и проверка согласованности оценщиков. Нельзя объявлять субъективную оценку объективным измерением без такой валидации.

Тестовый кейс показывает поведение в этом кейсе. Он не доказывает автоматически лидерство, надёжность, коммуникацию в реальной команде или способность управлять многолетней программой. Портфолио и внешние свидетельства можно учитывать отдельно с указанием источника.

## 7. Предлагаемый первый набор проверок

Для начала на нашем текущем примере: реализация логики на PHP / Java / JavaScript; SQL-запросы; API; транзакции; взаимодействие интерфейса с API; автоматические тесты; развёртывание контейнера; диагностика приложения в Kubernetes. Это предложение по пилоту, не универсальная программа для 120 специализаций.

Каждую область запускаем только после подготовки задания, критериев и контрольных результатов. Для остальных специализаций каталог остаётся доступным, но отсутствие методики явно обозначается.
